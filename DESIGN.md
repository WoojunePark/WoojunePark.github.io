# Design System: Woojune Park CV site

## Overview

**Creative North Star: "The Work Is the Poster"**

The site is a Swiss International Style poster built on a strict grid. The name is set at poster size, the results of each project are set as large bold sentences, and what matters most is biggest and first. Importance, not chronology, sets size and position: selected work leads with a figure and its results, publications follow as type rows, and the dated record is the smallest thing on the home page.

The material is ink on poster white. One grotesk (Archivo) carries every level of the hierarchy, from the name to a caption; contrast comes from size and weight alone. A heavy black rule opens every band, a label column names it, and hairlines separate rows. Red is the only colour and it is a signal, not a decoration. There is one scheme (light), no JavaScript, no motion, no shadows and no rounded corners. Diagrams for projects are drawn in the same black, white and red so a figure reads as part of the page.

The PDF CV is a different object on purpose: the same markup stripped to a plain single text column in a system face, with rules, dots and codes removed, so parsers and printers get uninterrupted text.

**Key Characteristics:**
- Size follows importance. The name, then project titles, then result sentences, then everything else.
- One typeface, two weights doing most of the work (700 and 400), 500 for the lede.
- One red, reserved for "current", the AI agents code, the arrival mark, hover and focus.
- A 6px black rule opens every band; a label column on the left names it from 64rem.
- Hairlines, not boxes: rows are separated by 1px lines, never enclosed.
- Square everything; the only curve is the red dot.
- Tabular figures everywhere.
- Static: no JavaScript, no transitions, no animation.

## Colors

Black on white with one red. Every other value is a grey that supports the ink.

### Primary
- **Signal Red** (`red`): the one colour. It marks the current page (the 3px underline under the nav link), the current role (the dot before it on the home page and on the CV), the "AI agents" code (solid fill), the entry a link landed on (a bar in the left margin), link and button hover, and the focus outline. In the project diagrams it marks the one outcome or the agent's own part of the picture.

### Neutral
- **Poster White** (`bg`): the page ground, the ground of every figure, and text on ink or red.
- **Ink** (`ink`): text, the heavy rules, the 2px rules, buttons, the outlined code, text selection.
- **Grey Ink** (`muted`): dates, organisations, venues, captions, band notes, tags, the line under the name.
- **Hairline** (`soft`): the 1px lines between rows, raster figure borders, the resting underline of entry-title links.

### Print only
- `print-bg`, `print-ink`, `print-muted`, `print-rule` and `print-link` belong to the PDF stylesheet. They never appear on screen. `print-link` is a conventional document blue for links in the PDF; it is not part of the screen palette.

### Named Rules

**The One Red Rule.** Red means current, arrived, or under the pointer or focus, plus the single "AI agents" code. It is never a heading colour, a background wash, a divider or a way to add emphasis to text. If a new element wants red, it must be one of those states.

**The No Second Colour Rule.** There is no second accent and no tint scale. Distinctions are made with size, weight, rule thickness and position.

**The One Scheme Rule.** The site is light only, by decision (`color-scheme: light`). Do not add a dark scheme.

## Typography

**Display Font:** Archivo Variable (self-hosted Latin subset in `assets/fonts/`, weight axis 100 to 900, SIL OFL 1.1), falling back to Helvetica Neue, Helvetica, Arial
**Body Font:** the same face and stack; Korean falls back to Apple SD Gothic Neo, Noto Sans KR, Malgun Gothic
**Label/Mono Font:** none; labels are the same face with tabular figures

**Character:** One grotesk at every size. Large sizes are bold and tightly tracked with very short leading, so headings stack like poster lines; reading sizes are regular weight with open leading. Nothing is uppercase and nothing is letter-spaced wider than normal on screen.

### Hierarchy
- **Display** (700, `display`, line-height 0.9, -0.04em): the name on the home page, spanning nine columns. Inner pages use **Page title** (700, `page-title`, 0.92, -0.04em).
- **Headline** (700, `headline`, 1.04, -0.03em): project titles.
- **Lede** (500, `lede`, 1.3, -0.018em): the single opening sentence on the home page, max 28em. The line under the name uses the smaller `name-sub` in grey ink.
- **Band label** (700, 1.375rem, -0.01em): the heading that names each band in the label column.
- **Result** (700, `result`, 1.3, -0.012em): result sentences under a project. Publication row titles (1.3125rem) and the year beside them sit at the same level.
- **Title** (700, 1.1875rem, 1.3): entry titles on the CV and publications pages and the current role. Organisation and group headings are 1.125rem.
- **Body** (400, 1.0625rem, 1.5): running text, capped between 34em and 44em depending on the block.
- **Secondary** (0.9375rem): navigation, links, dates, authors, venues, skills, footer. Bold when it is a link or a name, regular grey when it is metadata.
- **Label** (0.875rem, grey ink): project meta, tags, band notes, keywords. Captions are 0.8125rem; the code and figure credits are 0.75rem.
- **Diagram** (13px in SVG units, with 14px and 22px for emphasis): text inside the SVG diagrams, set in Helvetica Neue / Helvetica / Arial because an SVG loaded as an image cannot use the page's web font.

### Named Rules

**The One Face Rule.** Every level is Archivo. Do not introduce a second family for headings, labels or numbers.

**The Importance Sets Size Rule.** Size and position follow what matters, not when it happened. A date is never larger than the thing it dates, and the most important item in a band comes first regardless of its year.

**The Tabular Rule.** Figures are tabular everywhere so dates and years align down a column.

**The Sentence Case Rule.** Headings and labels are sentence case with normal or negative tracking. Uppercase tracked headings exist only in the PDF.

## Layout

A centred column (max 85rem) with a gutter of 1.125rem, 2rem from 40rem and 2.5rem from 64rem. Mobile-first; it holds at 320px with no horizontal scroll.

The page is a stack of bands. Each band opens with the 6px ink rule, then its label, then its content. Below 64rem the label sits above the content. From 64rem every band is a 12-column grid with a 1.5rem gap: the label column is columns 1 to 3 and the content sits on columns 4 to 12. The portfolio page has no label column, but its rows still start on column 4.

The home hero uses the same 12 columns: the name across columns 1 to 9, the portrait on 10 to 12, then the current role and links in the label column with the lede beside it on columns 4 to 9, both aligned to the bottom of their row.

Inside the content area a project with a figure splits into a 9-column grid: text on five columns, figure on four. A project without a figure keeps its text to the same five-column width. Rows are separated by space and a hairline: 2.25rem above and below between projects (2.75rem from 64rem), 1.125rem between entries and publication rows, 0.7rem between record rows.

From 40rem dated lists gain a fixed first column: 11rem for dates on the CV and in the home record, 5rem for the year in publication rows. Skills become three columns. Publication figures flow in columns of at least 16rem.

Bands have more room below than above (1rem above and 2.75rem below; 1.375rem and 4.5rem from 64rem), so the rule reads as the start of what follows.

**The Rule Opens the Band Rule.** A band always begins with the 6px ink rule. The rule is never used inside a band, and a band never begins without it.

**The Column Four Rule.** From 64rem, content starts on column 4. Only the name, the page title and the band labels may sit in columns 1 to 3.

## Elevation & Depth

None. The system is flat ink on paper: no shadows, no gradients, no blur, no translucent layers, no stacking other than the off-screen skip link. Hierarchy is carried by rule weight (6px, 2px, 1px), size and position.

**The Flat Sheet Rule.** If an element seems to need a shadow or a tinted panel to be noticed, it needs a rule above it, a larger size or an earlier position instead.

## Shapes

Everything is square: buttons, codes, figures and the portrait have no radius. The only curve is the red dot that marks the current role (a true circle, 0.7rem on the home page and 0.6rem on the CV).

Lines have four weights and each has one job: 6px ink opens a band and closes the top bar and footer; 3px is the current-page underline and the focus outline; 2px ink sits above result sentences, under organisation and group headings and above skill group names; 1px hairline separates rows and frames raster figures. The code has a 1.5px ink outline. SVG diagrams carry no frame.

The portrait is a square crop in grayscale with slightly raised contrast.

## Components

### Buttons
Solid, square, no border.
- **Shape:** square corners.
- **Primary:** ink ground, white bold text, padding 0.7rem 1.2rem. Used for the PDF download on the CV page. The top-bar "CV (PDF)" button is the same at 0.9375rem with padding 0.55rem 1rem, shown from 40rem.
- **Hover / Focus:** the ground switches to red, instantly. Focus is a 3px red outline offset 3px, the same on every focusable element.

### Codes (chips)
- **Style:** 0.75rem bold, padding 0 0.5rem, square, 1.5px outline. "3D vision" is ink outline on white; "AI agents" is solid red with white text.
- **State:** static labels placed before a project's meta line. Never interactive, never used for tags. Tags are a plain grey list separated by middle dots.

### Bands
- **Structure:** 6px ink rule, label (band label size, optional one-line grey note under it, max 15em), body.
- **Behaviour:** the label moves to the left column from 64rem. Bands carry a scroll margin so the rule is visible on arrival from a link.

### Project rows (signature)
- **Structure:** a headline-size title, a meta line (codes, then organisation in grey), a short summary (max 34em), then the result list, then tags; the figure sits to the right from 64rem and below the text on small screens.
- **Result list:** a 2px ink rule, then each result as a bold sentence at result size, each closed by a hairline. This is the signature of the system: results are set as lines to be read from across the room, not as bullets.
- **Figures:** SVG diagrams in ink, white and red with no frame; raster figures on white with a hairline frame and a height cap. The caption is 0.8125rem grey with the credit on its own smaller line.
- **Title links:** no underline at rest; a 3px underline on hover.

### Publication rows (home)
Year in the first column (bold, ink from 40rem), title at 1.3125rem bold beside it, venue line in grey with the venue name in ink. Rows are separated by hairlines. Title links underline on hover.

### Dated entries (CV and publications pages)
- **Structure:** date in an 11rem column (grey, 0.9375rem), title at 1.1875rem bold, detail below. Group and organisation headings sit above on a 2px ink rule.
- **Links:** entry-title links carry a 2px hairline-grey underline that takes the text colour on hover.
- **Current:** the current role's date is preceded by the red dot.
- **Arrival:** the entry a link landed on shows a red bar in the left margin beside its title.
- **Abstract:** a native disclosure; the summary is a bold word that turns red on hover, the body is 0.9375rem with a small grey source line.

### Navigation
- **Top bar:** name at left (bold, 0.9375rem), page links (500), "CV (PDF)" button at right, all closed by the 6px rule. On small screens the links wrap to a second row above the rule.
- **States:** links have no underline; the current page is bold with a 3px red underline; hover turns the text red.
- **Skip link:** ink ground, white bold text, appears at the top left on focus.
- **Footer:** opens with the 6px rule; name in bold, bold text links, a small grey update note.

### Inline links
Underlined at 1px in the text colour; on hover the text turns red and the underline goes to 2px. Link lists in the hero and footer are bold with no underline until hover.

### PDF (print page)
A4, margins 16mm 15mm, 10pt system sans in a single text column, always light. Rules, dots and codes are removed; entries become title left, date right, detail below. Section headings are 11.5pt uppercase with 0.04em tracking over a hairline. Keep it this plain: it exists for parsers and printers, and none of its values are to be used on screen.

## Do's and Don'ts

### Do:
- **Do** let importance set size and position: the strongest work first and largest, dates small and grey.
- **Do** open every band with the 6px ink rule and name it in the label column (columns 1 to 3 from 64rem), with content on columns 4 to 12.
- **Do** set results as bold sentences at result size under a 2px ink rule, one hairline after each.
- **Do** keep red for the current page, the current role, the "AI agents" code, the arrival bar, hover and focus.
- **Do** draw new diagrams in ink, white and red only, with red on the one outcome that matters.
- **Do** use the four line weights for their own jobs: 6px band, 3px current and focus, 2px group, 1px row.
- **Do** keep every figure tabular and every heading in sentence case.
- **Do** keep each page complete and ordered as plain HTML; dots and rules are generated content and must not carry information the text lacks.
- **Do** keep the PDF plain: one column, system face, no rules, dots or codes.

### Don't:
- **Don't** order or size content by chronology when importance says otherwise.
- **Don't** use red for headings, emphasis, backgrounds or dividers, and don't add a second colour or a tint.
- **Don't** add a second typeface, uppercase labels or wide tracking on screen.
- **Don't** add shadows, gradients, blur, cards or tinted panels.
- **Don't** round corners; the red dot is the only curve.
- **Don't** add JavaScript, transitions or animation.
- **Don't** add a dark scheme.
- **Don't** put content in columns 1 to 3 from 64rem unless it is the name, a page title or a band label.
- **Don't** frame SVG diagrams or recolour publication figures that come from papers.
